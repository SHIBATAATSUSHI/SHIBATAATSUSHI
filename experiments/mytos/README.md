# Mytos

端末で動くミニ・コーディングエージェント。Claude Code のようなものを、
中身が読み切れる分量で自作したもの。Anthropic Messages API のツール利用
ループを最小構成で組んであり、ファイルの読み書き・検索・シェル実行を
権限確認を挟みながら実行する。

## できること

- ファイルを読む・書く・部分編集する(`read` / `write` / `edit`)
- ファイル名と中身を検索する(`glob` / `grep`。`rg` があれば使う)
- シェルコマンドを実行する(`bash`)
- 思考の要約と本文をストリーミング表示する
- 実行の直前に確認を挟む(モードで強さを変えられる)
- 会話を保存して後から再開する

## セットアップ

```bash
cd experiments/mytos
pip install -r requirements.txt
export ANTHROPIC_API_KEY=sk-ant-...   # または `ant auth login`
```

`pip install -e .` すると `mytos` コマンドとして入る。入れずに
`python -m mytos` でもそのまま動く。

## 使い方

```bash
# 対話モード(カレントディレクトリが作業対象)
python -m mytos

# 1回だけ実行して終了
python -m mytos -p "tests/ 以下のテストを実行して、落ちているものを直して"

# 別ディレクトリを対象にする / モデルと深さを変える
python -m mytos -C ~/work/myapp -m sonnet -e medium

# 標準入力から指示を渡す
git diff | python -m mytos -p "この差分をレビューして"

# 前回の続きから
python -m mytos --resume
```

### 主なオプション

| オプション | 説明 |
| --- | --- |
| `-m, --model` | `fable` / `mythos` / `opus`(既定) / `sonnet` / `haiku`、または任意のモデルID |
| `-e, --effort` | `low` / `medium` / `high`(既定) / `xhigh` / `max` |
| `--mode` | 権限モード。`ask`(既定) / `auto` / `yolo` |
| `-C, --workspace` | 作業ディレクトリ。ファイル操作はこの外に出られない |
| `--max-tokens` | 1リクエストの出力上限(既定 32000、思考トークンを含む) |
| `--thinking` | `summarized`(既定)で思考の要約を表示、`omitted` で非表示 |
| `--resume` | 最後に保存したセッションを再開 |

環境変数 `MYTOS_MODEL` / `MYTOS_EFFORT` / `MYTOS_MODE` で既定値を変えられる。

### 対話中のコマンド

```
/help              コマンド一覧
/model [名前]      モデルの表示・変更
/effort [段階]     effort の表示・変更
/mode [モード]     権限モードの表示・変更
/max-tokens [N]    出力上限の表示・変更
/tools             ツール一覧
/cost              トークン利用量と概算コスト
/clear             会話履歴を消す
/save              セッションを保存
/exit              終了(Ctrl-D も同じ)
```

## 権限モード

| モード | ファイル変更 | シェル実行 |
| --- | --- | --- |
| `ask`(既定) | 毎回確認 | 毎回確認 |
| `auto` | 自動 | 毎回確認 |
| `yolo` | 自動 | 自動 |

`auto` でも、`rm -rf` / `sudo` / `git push` / `curl \| sh` のような
取り返しがつきにくいコマンドは確認を挟む(`permissions.py` の
`RISKY_PATTERNS`)。読み取り専用ツールはどのモードでも確認しない。

`yolo` は文字どおり全部素通しなので、使い捨てのコンテナなど
壊れても困らない環境だけで使うこと。

## 設計メモ

作るうえで効いた判断を残しておく。

**作業ディレクトリの外に出さない。** モデルが渡してくるパスは信頼できない
入力なので、`Workspace.resolve()` を必ず通す。`..` と絶対パスに加えて、
シンボリックリンクを展開したあとの位置も見て境界を判定する
(未作成のパスも扱えるよう、実在する祖先まで遡ってから解決する)。

**編集前に読ませる。** `edit` は、そのファイルを `read` していないと失敗する。
さらに `read` 以降にファイルが変わっていた場合も失敗させ、読み直しを促す。
専用ツールにしておくと、こうした不変条件をハーネス側で強制できる。
`bash` に `sed` を打たせていたら同じことはできない。

**ツール結果は1通にまとめる。** 並列に呼ばれた複数のツールの結果を別々の
メッセージに分けて返すと、モデルは並列呼び出しをやめてしまう。
`Session.append_tool_results()` で必ず1つの user メッセージに束ねる。

**プロンプトキャッシュを壊さない。** システムプロンプトとツール定義は
リクエストの先頭に載るので、ここが1バイトでも変わるとそれ以降の
キャッシュが無効になる。システムプロンプトはセッション中固定にし
(実行時刻のような毎回変わる値を混ぜない)、ツールの並びも登録順で固定する。
`/model` でモデルを変えるとキャッシュは作り直しになる。

**失敗はモデルに返す。** ツールが失敗しても落とさず、`is_error` 付きの
`tool_result` として返して回復させる。ユーザーが実行を拒否した場合も同じで、
「拒否された」と伝えれば別の手を考える。

**モデルごとの差を設定に持つ。** adaptive thinking と `effort` は
現行世代のモデルにしか送れず、Haiku 4.5 に送ると 400 になる。
どのパラメータを送ってよいかを `ModelSpec` に持たせ、リクエスト組み立て時に
参照する。Fable / Mythos ではサーバ側フォールバックを有効にして、
安全性分類器による `refusal` を別モデルで救済する。

**停止理由を全部さばく。** `end_turn` / `tool_use` だけでなく、
`refusal`(拒否)、`max_tokens`(出力上限で途中終了)、
`pause_turn`(サーバ側ツールの区切り。同じターンで続きを要求する)を
それぞれ処理する。`content` を無条件に読むと拒否時に壊れる。

## テスト

```bash
cd experiments/mytos
python -m unittest discover -s tests
```

113件。内訳は、パス境界・各ツール・設定と権限判定・セッション保存・
CLI の引数解釈とスラッシュコマンドに加えて、

- `test_agent.py` — フェイククライアントを差し込み、停止理由の分岐・
  ツール往復・権限拒否・往復上限の挙動を検証する
- `test_integration_sse.py` — ローカルに Messages API を模した SSE サーバを
  立て、**本物の anthropic SDK** をそこへ向ける。SDK のストリーミング解析を
  通ったあとにループが正しく動くところまで確認する。外部通信はしない

## 制限

- 会話履歴の圧縮(コンパクション)は未実装。長い会話はコンテキスト上限に当たる
- サブエージェント、MCP、Web検索には対応していない
- `.gitignore` は見ておらず、除外は `IGNORED_DIRS` の固定リスト
- 実 API に対する疎通確認はしていない(この環境に認証情報が無いため)。
  SDK 経路はモックサーバで検証済み
