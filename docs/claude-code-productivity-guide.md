# Claude Code 生産性爆上げガイド

OpenAI ニュースレター(2026年7月号)で紹介されていた Codex / Work のトップユーザーの手法を、Claude Code の機能に翻訳して「インストール」したもの。このリポジトリの `.claude/` 配下に実装済み。

## 手法の対応表

| ニュースレターの手法 (Codex) | Claude Code での対応物 | このリポジトリでの実装 |
|---|---|---|
| `/goal` でゴール・制約・完了の証明を定義し、review→repair→validate ループで自走 | プランモード + 検証ループ | `/goal` スキル |
| サブエージェントスレッドに独立作業を分割して並列実行 | Agent ツール (Explore / Plan / general-purpose) | `/parallel` スキル |
| 専門家の修正を評価とタスクに変える自己改善エージェント | CLAUDE.md への学習の蓄積 | `/self-improve` スキル + CLAUDE.md の学習ログ |
| AGENTS.md / Skills を監査して重複・過剰な指示を削る | CLAUDE.md / SKILL.md の監査 | `/audit-instructions` スキル |
| ワークフローを Skill としてパッケージ化して再利用 | `.claude/skills/` | この4スキル自体がその実例 |
| Workspace Agent をスケジュール・トリガーで起動 | Routines(cron)/ `/loop` / セッションへの send_later | 必要になったら会話から設定(下記) |
| 安定したプロンプト前置をキャッシュしてコスト削減 | CLAUDE.md を薄く安定に保つ(自動でキャッシュされる) | CLAUDE.md の「スリムに保つ」原則 |
| PR Chat / Codex による差分編集とPRレビュー | `/review`・`/code-review`・PR監視 (subscribe_pr_activity) | 標準機能をそのまま使う |

## 日常の使い方(トップユーザーの型)

### 1. 大きめの仕事は `/goal` で始める

「完成の定義」を先に固定してから走らせるのが最大の生産性差。

```
/goal 衝動の定義大全に「神経科学」の章を追加して。既存の章と同じ構成で、参考文献付き。
```

Claude がゴール・制約・完了の証明を宣言し、検証が通るまで途中で止まらず自走する。

### 2. 調べ物・独立作業は `/parallel` で分割

```
/parallel 哲学・心理学・宗教それぞれの章の引用元の実在を確認して
```

3つ以上の独立作業があれば、サブエージェントに分けて同時に走らせ、統合結果だけ受け取る。

### 3. 直しを入れたら `/self-improve`

「そうじゃなくて◯◯」と直したら、その学びを CLAUDE.md の学習ログに1行で蓄積させる。次のセッションから最初に効いてくる。これが「使うほど賢くなる環境」の正体。

### 4. 月1回 `/audit-instructions`

指示は溜まるほど効かなくなる。定期的に監査して、重複と死んだ指示を削り、学習ログを原則に昇格させる。**薄い指示ほど守られ、キャッシュも効く。**

### 5. 出荷前は reviewer サブエージェントに見せる

`.claude/agents/reviewer.md` に批評専任のエージェントを定義済み。「reviewer エージェントでレビューして」と言えば、書いた本人とは別の目で指摘だけが返ってくる。

### 6. 定期実行したくなったら

「毎朝9時に◯◯して」と言えば Routines(スケジュールトリガー)を設定できる。ニュースレターの「Workspace Agent + スケジュール + トリガー」に相当。

## 設計思想

- **指示より仕組み**: 長い指示書ではなく、スキル(呼び出せる手順書)として実装する。必要なときだけコンテキストに載るので、常時コストがかからない。
- **完了の証明を先に決める**: 「done の定義」が曖昧な仕事は往復回数が爆発する。先に固定する。
- **修正は資産**: 同じ指摘を2回させたら仕組みの負け。学習ログに落とす。
- **薄さは機能**: CLAUDE.md が薄く安定しているほど、モデルは守り、キャッシュが効き、速く安くなる。
