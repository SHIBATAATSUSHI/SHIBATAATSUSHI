# note 運用方針(note.com/19770104 — 筆名: 夏目漱右)

自動化スクリプト(`scripts/note_post.py` / `scripts/note_lint.py`)が何のために作られているかの前提。
別ツールで検討した内容をここに集約し、原稿の書き方とチェック項目の根拠にしている。

## 軸(2026-08 更新)

> **大学病院で働く理学療法士が、高度急性期の臨床・若手教育・組織運営で培った実践知を、
> AI時代に使える形へ再構成する。**

以前の軸は「理学療法士 × 脳神経リハ × AI活用」だったが、AI活用だけを前面に出すと
「AIの使い方を紹介する人」に埋もれる。臨床・教育・組織の実践知を主にし、
AIはそれを再構成する手段として置く。

### 発信の4本柱

1. **高度急性期における臨床判断・臨床思考**
2. **若手リハ職への教育** — 問いかけ、判断根拠の引き出し方
3. **病院という複雑な組織の運営・仕組み**
4. **医療職による生成AIの安全で実践的な活用**

- 想定読者: 若手〜中堅のリハビリ職(PT・OT・ST)
- 差別化の核: 「大学病院」「高度急性期」「臨床・教育・管理の三役」「AIも実践している」
- 一般向けの健康情報(姿勢改善など)は主軸にしない。読者は広がるが、医療広告・安全性の配慮が増え、差別化もしにくい
- 10本公開したあと、反応を見て主軸を1本に絞る

## 本人性(記事の「自分で書く部分」の材料)

記事がAI生成物に見えないのは、この判断原則が入っているとき。抽象論ではなく、
どれも現場での判断の形をしている。

- 指示が伝わらないとき、相手ではなく**自分の言葉を変える**
- 臨床推論は正解を当てることではなく、**反応を見て修正する循環**(仮説→介入→反応→修正)
- 予定を完遂することより、**反応を見て止める**判断を重視する
- 患者数だけで高度急性期の負担を測らない
- 会話も、覚醒・注意・疲労・生活目標を知る**評価**になる
- 安全基準を、現場で継続できる**運用**へ変換する(禁止で終わらせず、相談先と確認地点まで設計する)
- AIへのプロンプトは、患者説明や若手教育の**練習**になる
- AIで効率化した後、**その余白を何に使うか**が重要
- 一つの資格・所属先・コミュニティだけに依存しない

### 記事に使ってよい実体験

安全化済みとして確認された範囲。患者・職員の個別エピソードは含まない。

- AIによるポスター制作と、画像補正で人物の顔や身体が変わってしまった失敗
- アプリ試作へのAI活用
- 研修内容を文字・スライド・音声へ変換して学び直す方法
- 研究計画が環境変化で止まり、関心を別分野へ広げた経験
- note の公開操作だけは本人が行う設計にしていること

### 使ってはいけないもの

- 患者・職員の個別エピソード(声の記録に由来するものを含む)
- 院内の運用・勤務・検査値など、施設が推定できる情報
- 記録で確認できない経験(創作しない)

## 記事の順番

最初に出すのは**固定記事**。過去記事を残したまま、今後の方向を説明する。

1. 固定記事「このnoteで、これから発信すること」
2. 医療職が生成AIを使う前に決めたい境界線
3. 理学療法士が生成AIで論文を読むときの確認手順

2本目を先に置くのは、安全性への姿勢を示してから AI・論文の話に入るため。

### 連載候補

- 若手の臨床推論に芯を作る3つの質問
- 完遂しない判断 — 予定より患者の反応を優先する
- 高度急性期では患者数だけで仕事量を測れない
- 病院を複雑適応系として見る
- プロンプトは、患者説明と若手教育の練習になる

## 既存記事の扱い

削除しない。検索流入と過去の反応を残したまま、マガジンで整理する。

- 人間を考える(意志・時間・社会・生き方)
- リハビリテーションの未来を考える
- 理学療法士とAI(安全に試し、仕事へつなぐ)
- 姿勢とセルフケア / 認知症・脳神経リハ / 組織とキャリア

新着記事だけを4本柱に統一し、プロフィールと固定記事で方針転換を説明する。

## 無料・有料の設計

| 位置 | 扱い |
| --- | --- |
| 1〜7本目 | 無料。専門性と信頼を作り、どの悩みに反応があるかを見る |
| 8本目 | 無料。チェックリストを公開し、保存需要を確認する |
| 9本目〜 | 反応が良かった内容を有料化。980〜1,980円を想定 |

- 最初の有料候補: **判断根拠を引き出す質問集 ＋ AI・後輩・患者への依頼設計テンプレート**
  (確定ではない。公開後のビュー・スキ率・質問・保存需要を見て調整する)
- 有料記事には「情報」だけでなく、**そのまま使えるもの**(質問集・チェックリスト・テンプレート・記入例・失敗例)を含める
- メンバーシップは有料記事が数本売れ、反応を確認してから検討する
- 個別症例への医療相談・診断にあたるサービスは提供しない

> 市場データ(成長ジャンル・平均単価など)は別ツールでの調査に基づく引用で、
> **このリポジトリでは未検証**。記事中で数値を引用する場合は一次情報を自分で確認すること。

## 自動化する範囲

医療テーマのため、**完全自動公開はしない。**

```
テーマ選定 → 調査 → 原稿作成 → 本人の判断原則・経験を追記
  → 公開前チェック(scripts/note_lint.py)
  → note へ下書き保存(scripts/note_post.py)
  → 人間が目視確認 → note 上で公開
```

| 自動化する | 人間が行う |
| --- | --- |
| 原稿の流し込み、既存記事の上書き | 医学的妥当性の確認 |
| タイトル・タグの設定 | 患者情報・所属規程の確認 |
| 定型句・断定表現・出典欠落の検出 | 引用の妥当性、経験談の事実確認 |
| 公開前確認票の生成 | 見出し画像の設定と公開ボタン |

そのため `config/note_accounts.json` の `allow_publish` は `false` を既定にしている。

### 音声からの取り込み(別プロジェクト)

「アウトプットキャッチ」で本人の発話を抽出・文字起こしし、記事候補として渡す流れが
別プロジェクト側に用意されている。このリポジトリはまだ接続していない。

```
音声抽出 → 端末内で文字起こし → 患者・職員・施設情報の危険判定
  → 本人の判断・学びだけを抽出 → 実践知へ変換 → 記事候補 / 研究課題候補
```

接続する場合の原則:

- **「本人の声だけ」でも自動的に安全にはならない。** 本人の発話に患者の病状・検査値・
  職員・勤務・院内運用が含まれうる。文字起こしから直接記事を作らず、安全化を必ず挟む
- 自動送信しない。本人が確認してボタンを押したものだけが記事候補になる
- 研究利用は初期状態で「許可されていない」として扱う

### 論文化について

過去の記録をそのまま研究データにはしない。研究を目指すなら、倫理確認を経てから、
患者・職員の情報を含まない形式で本人の省察を**前向きに**収集する。

- 人を対象とする医学系研究は、科学的合理性・倫理審査・事前説明と同意・個人情報管理が前提
- AIは著者にしない。使ったツールと目的を開示し、正確性と引用には人が責任を持つ(ICMJE)
- 質的研究として扱うなら COREQ などの報告基準を参照する

## 文体ルール

原稿を書くとき、および `scripts/note_lint.py` が見ているもの。

- **主語「私は」を使わない。** 誰の判断かは文脈と語彙で示す(「学生の頃」「ポスター制作を補助した際」など)
- 同じ書き出しの文を続けない
- 定型句を置かない — いかがでしたか / まとめると / 結論から言うと / ではないでしょうか / 深掘り / 本質的に / 言っても過言ではない
- 「AではなくB」型の対比を繰り返さない
- 文の長さを揃えない。短い文を混ぜる
- 一文は100文字以内を目安にする
- 感嘆符・絵文字は使わない
- 専門的で、長さのある文章にする

## 書いてはいけないこと

`note_lint.py` が「重大」として止める項目。

- 治癒・改善の断定(「必ず治る」「確実に改善」)
- 診断行為・受診回避の示唆
- 服薬の変更・中止の示唆
- 個別症例と読める記述(「68歳男性」「症例A」)、診療録・担当患者への言及
- 所属施設が推定できる記述(「当院」「勤務先の病院」)

「要確認」として警告する項目。

- 断定・一般化(必ず / 絶対に / 誰でも)、最上級表現(日本初 / 最高の)
- 研究・数値に触れているのに出典URLがない
- タイトルの一人称
