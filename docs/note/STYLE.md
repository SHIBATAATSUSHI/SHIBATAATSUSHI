# note 記事の文体ガイド

`akutagawa_tora` に投稿する記事の書き方。ルールはここに集約し、守れているかは `uv run scripts/note_lint.py <ファイル>` で**実測**する。

書きすぎない。守れるものだけを載せ、守れなかったものは消す。

## 一人称の扱い

**本文中の「私は」は原則0を目指す。** タイトルと見出しは対象外。

数えるのは「私は」だけではない。**「私が」「私に」「私の」「僕」「わたし」を含めた一人称全体**を見る。「私は」だけを数えると、置き換えたつもりで別の形の一人称が残る(実際、既存2本ではそれぞれ1件・2件が見落とされていた)。

ただし**単に主語を削らない。** 主語を消すだけだと、誰のいつの判断なのかが分からない文章になる。判断主体と時点が分かる表現に**置き換える**。

| 置き換え前 | 置き換え後 |
|---|---|
| 私は大学院で〜 | 大学院時代には〜 |
| 私は臨床で〜 | 臨床や教育では〜 |
| 私はまだ〜だった | 当時の自分は〜だった |
| 私はこの本を読んで〜 | この本を読みながら〜 |

「自分」は禁止語ではない。「当時の自分」は推奨される置き換え先で、lint も検出対象から外している。

### 残してよい例外

**その一文から一人称を消すと、誰の思想・経験なのかが特定できなくなる場合**は残す。目安は次の2つ。

- ある思想や立場に対する**書き手自身のスタンス**を明示する箇所
- 書き手が**実際に経験したこと**の出所を示す箇所(誰かに何を話したか、など)

残す場合はフロントマターで数を申告する。申告の範囲内なら lint は指摘しない。

```markdown
---
title: 記事のタイトル
allow_first_person: 2
---
```

申告は「うっかり残った」と「考えて残した」を区別するための仕組み。数だけでなく、**なぜ残したか**を推敲時に説明できる状態にしておく。

## 文字数

**本文3,500〜5,000字。** 既存記事の実測を根拠にしている。

| 記事 | 本文のみ | 関連書籍セクションを含む |
|---|---|---|
| 01 なぜ、忙しかった頃の私は本が読めなかったのか | 3,963字 | 4,474字 |
| 02 生活に仕事の論理を持ち込むと、夫婦はなぜ黙るのか | 3,988字 | 4,502字 |

## 一文の長さ

**中央値75字前後。150字を超えたら見直す。**

短く切ることは推奨しない。既存2本では100字超の文が22〜33%あり、**長い一文はこのアカウントの文体そのもの**。一文の中で経験・概念・留保が動く書き方を保つ。

lint の閾値150字は、実測の95パーセンタイル(145字前後)から決めた。本当の外れ値だけが引っかかる。

## 決め台詞を置かない

## 見出しと構成

note には h2 と h3 しかない。`#` と `##` は h2、`###` 以降は h3 に丸められる。`####` を書いても意図した階層にはならない。

記事全体の流れは `docs/note/CONCEPT.md` の「記事の基本構成」に従う(具体的な出来事 → 名前のない違和感 → 本の概念 → 経験の読み直し → 残る疑問)。

## 決め台詞を置かない

短い決め台詞や、機械的な「XではなくY」の構文を並べない。一文の中で経験・概念・留保が動く書き方にする。

断定で段落を締める癖がつくと、考えている過程ではなく結論だけが残る。このアカウントが書くのは結論ではなく、見え方がどう変わったかのほう。

## 文末とトーン

- 同じ文末が3文続いたら崩す(lint が拾う)
- 一文は100字を超えない。超えるなら切る

## まだ読んでいない本の書き方

このアカウントは、読む前の本を先に名指しする。記事01の「これから老子や荘子を読み…足場になると思う」がその形。**未読であること自体は弱点ではないが、読んだふりをすると一度で信用を失う。**

書いてよいもの:

- 書誌情報(書名・著者・出版社・副題)
- **こちらの見込みと、読もうとしている理由**

書いてはいけないもの:

- 内容の断定。「〜と論じている」「〜が分かる」「〜が見えてくる」「〜をたどれる」

| ✗ 断定 | ○ 見込み |
|---|---|
| 労働が倫理になる過程の由来をたどれる | どこから来たものなのかを遡るために読もうとしている。まだ手をつけていない |
| 暇と退屈を分けて考えると違う姿で見えてくる | 暇と退屈という区別から読み直せないかと考えている |

副題や書名に書いてあることは事実なので、「副題に意志と責任の考古学とあるので、そこを頼りに読むつもりでいる」のように**手がかりとして示すのはよい**。

読了状況は `docs/note/books.yaml` の `read` で管理する。`read: false` の本に断定表現を使うと lint が警告する。読み終えたら `true` にする。

## 関連書籍は効用ではなく接続で書く

記事末尾に「この本から続く本」を3〜4冊置く。書誌は `docs/note/books.yaml` から取る(手で書くと出版社や版を取り違える)。

- ✗「この本を読めば、思考の解像度が上がります」
- ○「ノイズを受け取る余白を失っていた、と書いた部分は、暇と退屈を分けて考えると違う姿で見えてくる」

あらすじは書かない。**記事本文が自分で名指しした本**だけを扱い、記事のどこから続くのかを1〜2文で書く。記事01が「用途を説明できる本だけが残った」と書いている以上、効用で本を薦めると看板と中身が食い違う。

## 自分向けのメモは投稿範囲から外す

推奨タグ・見出し画像案のようなメモは、`<!-- 投稿しない -->` マーカーより下に置く。マーカーが無いと**そのまま公開記事の末尾に出る**。タグはフロントマターの `tags:` に書けば note へ渡る。

## note で使えない記法

表・脚注・生の HTML は解釈されず、そのまま文字として出る。表は箇条書きか画像に置き換える。lint が拾う。

## このガイドの育て方

文体の指摘を受けたらこのファイルに反映する。CLAUDE.md の「学習ログ」は Claude の振る舞い用、こちらは文章用として役割を分ける。

ルールは一般論の文章読本からではなく、**実際に書けた記事**から抽出する。
