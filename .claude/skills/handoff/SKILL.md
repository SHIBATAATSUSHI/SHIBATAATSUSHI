# /handoff — 端末をまたぐ引き継ぎ

Mac のローカルセッションとケータイのクラウドセッションは別プロセスで、会話は共有されない。共有できるのは git リポジトリだけ。そこで `docs/handoff.md` を「現在地の置き場」として使う。

## 判断

まず今どちらをするか決める。

- ユーザーが**再開しようとしている**(「続きから」「/handoff」だけで文脈が無い、セッションの冒頭)→ **読む**
- ユーザーが**切り上げようとしている**(「今日はここまで」「いったん中断」「あとでケータイでやる」)→ **書く**
- どちらとも取れるなら、まず読んでから「続けますか、それとも今の状態を書き出しますか」と聞く。

## 読む

1. `docs/handoff.md` を読む。無ければ「引き継ぎメモはまだ無い」と伝えて終わり。
2. `git log --oneline -5` で、メモが書かれた後に何が起きたか確認する。
3. ユーザーに **3行以内**で要約して伝える: 前回どこまで / 次にやること / 注意点。
4. そのまま「次にやること」に着手してよいか確認し、了承されたら進む。

## 書く

`docs/handoff.md` を**丸ごと上書き**する(追記しない。過去ログは git 履歴が持っている)。

```markdown
# 引き継ぎメモ

最終更新: YYYY-MM-DD / 端末: <Mac ローカル or クラウド(ケータイ)>
ブランチ: <branch-name>

## 前回どこまで
- (完了したことを箇条書きで3つまで)

## 次にやること
1. (次の一手を具体的に。ファイルパス付きで)

## 注意点
- (詰まっている点、判断待ちの点。無ければ「なし」)
```

書いたらコミットして push する。push まで済ませないと別端末から見えないので、必ず最後まで通す。

```bash
git add docs/handoff.md && git commit -m "引き継ぎメモを更新" && git push -u origin <branch>
```

## 注意

- 書く内容は**次の一手が分かる最小限**に絞る。会話の全文要約は書かない(読む側のコンテキストを食うだけ)。
- ローカル作業を Mac 上でそのまま続けたいだけなら、引き継ぎメモより Remote Control(`claude --remote-control`)のほうが速い。手段の選び方は `docs/mac-mobile-sync-guide.md` を参照。
- クラウドセッションで書く場合、作業ブランチが main と違うことが多い。どのブランチに書いたかをメモ本文に必ず残す。
