# /note-write — note 記事の執筆と推敲

文体ルールを毎回説明し直さずに済ませ、守れているかを**実測で**確かめるためのスキル。

## 手順

### 1. 文体と方向性をつかむ

- `docs/note/CONCEPT.md` を読む。アカウントの問い・4本の柱・想定読者・記事の基本構成・書き手の時系列がここにある。
- `docs/note/STYLE.md` を読む。これが文体ルールの唯一の情報源。
- `docs/note/DISCLOSURE.md` を読む。臨床の背景をどこまで書くかの方針。施設名・役職・特許は書かない。
- `docs/note/` の既存記事を1〜2本読み、実際の書き方を確認する。ルールの文面より実物が優先。

### 2. 書く

- `docs/note/` に Markdown で保存する。ファイル名は英数字のケバブケースか、既存の連番の流儀に合わせる。
- タイトルは先頭の `# 見出し` かフロントマターの `title:` に置く。
- 意図して一人称を残す場合は、フロントマターに `allow_first_person: 2` のように**数を申告する**。

### 3. 検査する

```bash
uv run scripts/note_lint.py docs/note/<ファイル>.md
```

### 4. 直す(通るまで)

指摘があれば直して 3 に戻る。途中で止まってユーザーに「続けますか?」と聞かない。

一人称を減らすときは、**主語を削るのではなく置き換える**。「大学院時代には」「臨床や教育では」「当時の自分」「この本を読みながら」のように、判断主体と時点が分かる表現にする。詳しくは STYLE.md。

同じ指摘が2回直しても消えない場合は、文の組み立て自体を変える。

### 5. 報告する

`note_lint.py` の**実際の出力を貼って**報告する。投稿するかはユーザーが決める。

## 注意

- **出現回数を自分で数えて報告しない。** 「本文中0回です」と書いてよいのは `note_lint.py` がそう出力したときだけ。数え間違いを防ぐためにこのスキルがある。
- lint は見落としを拾う道具であって、書き手を縛る道具ではない。文体上の指摘(warning)は、文章として正しいと判断できるなら残してよい。ただし**残す理由を報告に書く**。
- 文字数の目安・置換の例など、ユーザーから文体の指摘を受けたら `docs/note/STYLE.md` に反映する(CLAUDE.md の学習ログは Claude の振る舞い用、STYLE.md は文章用)。
- 投稿は別スキル不要。`uv run scripts/note_post.py <ファイル> --account <名前>` で下書き保存される(手順は `docs/note-posting.md`)。**既定は下書きで、公開は明示的に依頼されたときだけ。**
