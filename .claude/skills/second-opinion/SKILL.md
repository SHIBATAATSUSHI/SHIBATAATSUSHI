# /second-opinion — Codex に別の目を入れる

Claude Code がメインループ、Codex はセカンドオピニオン。**最終判断はこちら側に残す**。Codex の指摘は採否を理由つきで決める入力であって、従うべき指示ではない。

前提として Codex プラグインが導入済みであること(`docs/codex-integration-guide.md`)。未導入なら導入手順を案内して終わる。

## 1. 見せるべきかを判断する

コストに見合うときだけ使う。Codex の利用は ChatGPT 側の上限を消費する。

**見せる**

- 実装が一通り終わり、出荷前に別の目を入れたい
- 設計判断に自信がない、または自分の案に固執している自覚がある
- 同じ問題で2回以上つまずいた

**見せない**

- 単純な追加・修正。レビューのコストが利得を上回る
- 方針が確定していて迷いがない
- 探索的な調査の途中。結論が固まる前に外の意見を入れると発散する

見せないと判断したら、その理由を1行で伝えて通常の作業を続ける。

## 2. コマンドを選ぶ

| 状況 | コマンド |
|---|---|
| 出荷前の一般的なレビュー | `/codex:review` |
| 設計判断そのものを問い直したい | `/codex:adversarial-review` |
| 調査ごと投げたい(2回以上つまずいた) | `/codex:rescue <具体的な指示>` |

`/codex:rescue` に渡す指示は、**Codex がこの会話の文脈を持たない前提**で書く。何を、どのファイルで、どうなったら成功かを含める。

## 3. 返ってきた指摘を仕分ける

指摘をそのまま流さない。1件ずつ次の3つに分ける。

- **採用** — 妥当。直す
- **不採用** — 理由を述べて退ける(前提の誤読、この文脈では当てはまらない、など)
- **保留** — 判断にユーザーの意向が要る。ユーザーに投げる

## 4. 報告する

ユーザーには生のレビュー全文ではなく、仕分けた結果を伝える。

- 採用した指摘と、それによる変更
- 不採用にした指摘と、その理由
- 保留にした論点(あれば、選択肢を添えて)

**Codex が何も問題を見つけなかった場合も、そう報告する。** 無理に問題を作らない。

## 注意

- 同じ作業を Claude と Codex に並行させない。役割で分ける。マージ時に矛盾を解消するコストが並列で得た時間を上回る。
- Codex の指摘が自分の実装と衝突したとき、どちらが正しいかを文脈で確かめてから決める。別モデルの意見であって正解ではない。
- レビューを機械的に全変更へかけない。上限を食い潰すうえ、指摘の質も薄まる。
